## Quality and remaining risks

- **Test independence:** top-level tests run serially by Node's default, and `beforeEach` clears the disposable `rate_limits` collection. The inactive-account case restores status in `finally`. `after` closes the HTTP server, disconnects Mongoose and stops the replica set. Two independent test processes (local and platform) completed and exited normally.
- **Flakiness risk:** a rate-limit test could cross a 900-second bucket boundary during its series of requests; this is unlikely but not controlled by a fake clock. Cold CI may need to download MongoDB 7.0.24; the 90-second setup timeout could be insufficient on a slow runner. The test does not depend on production services.
- **CI discovery gap:** root `npm test` runs workspace test scripts and `test:platform`, but Auth has no `test` script. Therefore the new Auth-local test is **not automatically discovered by root `npm test`**; it was explicitly run here. Adding it to CI would require a separately approved scope change because the user's COOK approval constrained source changes.
- **Coverage limits:** the new test does not directly exercise `/api/v1/auth/*` alias or a successful normal-user `change-password` request. The shared router mount and existing platform cases support compatibility, but direct coverage would improve confidence. No observed product failure resulted from these gaps.
- **No leak observation:** tested login and introspection responses do not expose raw JWT in JSON or set a cookie on introspection; fixture credentials are synthetic. Reset response paths were inspected unchanged and platform audit test checks no password/token/email in audit records. This is not a production log audit.
- Mail-delivery and login-audit failure policy risks from SCOUT remain outside the approved change. No new product bug was observed in this TEST.
